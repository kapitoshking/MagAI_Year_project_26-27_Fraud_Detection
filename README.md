**Формула оценки: O = 0.5 * N + 0.325 * (O_predefense + O_defense),**

- где N - число полностью сделанных в срок чекпойнтов,
- O_predefense = O_defense = 0.6 * индивидуальная оценка куратора за полугодие + 0.4 * командная оценка комиссии на защите.
Ниже вы найдете подробное описание текущих и прошедших чекпойнтов, а также краткое описание будущих контрольных точек с ориентировочными дедлайнами.

Описание чекпойнтов дано для ML-трека. Для DL и research-треков чекпойнты будут незначительно отличаться, но чекпойнт 4, промежуточная и итоговые защиты - одинаковые для всех треков.

## [GitHub Годового проекта. Обнаружение аномалий / Fraud Detection](https://github.com/kapitoshking/MagAI_Year_project_26-27_Fraud_Detection)

## **Руководитель, куратор:** Мовсумов Денис

- **Тип задачи:** anomaly detection, крайне несбалансированная классификация
- **Данные:** [Credit Card Fraud Detection — ULB (Kaggle)](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud), [IEEE-CIS Fraud Detection
(Kaggle)](https://www.kaggle.com/c/ieee-fraud-detection)
- **Методы:** Isolation Forest, One-Class SVM, Local Outlier Factor; сравнение с supervised (XGBoost + class weighting) 
- **Метрики:** PR-AUC (важнее ROC-AUC при сильном дисбалансе), Recall при фиксированном Precision
- **Усложнения:** потоковое (online) обнаружение; объяснение решений модели для комплаенса
- **Уровень:** BASE/MIDDLE
- **Проблема:** часть транзакций — мошеннические, их пропуск ведёт к прямым финансовым потерям, а ложные срабатывания раздражают добросовестных клиентов.
 
**Что сделать?:** построить модель обнаружения аномальных/мошеннических транзакций в потоке данных. 

**Возможные задачи:** 
- EDA, анализ дисбаланса и типов аномалий 
- построение unsupervised baseline (Isolation Forest)
- обучение supervised модели с балансировкой классов
- подбор порога под целевой Precision/Recall
- анализ ложных срабатываний
- описание процесса интеграции в мониторинг

**Критерии приемки:** модель достигает целевого Recall при заданном уровне 
Precision (или PR-AUC выше baseline); протестирована устойчивость к 
дисбалансу классов; описан процесс принятия решения (порог, объяснение 
флагов) для интеграции в процесс проверки.
